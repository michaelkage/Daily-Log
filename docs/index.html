Configuration / repository Actions settings

Required by scripts

The shared GitHub client throws at startup unless both variables are present.

GITHUB_TOKEN=...
GITHUB_REPOSITORY=owner/repository

Workflows provide these from secrets.GITHUB_TOKEN and github.repository. They are not committed to the repository.

Optional cross-repository activity

GH_ACTIVITY_REPOS=owner/repo-a,owner/repo-b
GH_ACTIVITY_TOKEN=read-only-token

Set GH_ACTIVITY_REPOS as an Actions variable and GH_ACTIVITY_TOKEN as a secret. If absent, the activity reader falls back to GITHUB_TOKEN. Writes always use GITHUB_TOKEN.

There is no package.json, dependency install, local CLI wrapper, database, server process, or separate backend in the current tree. The scripts are Node.js ES modules that use built-in fetch, Buffer and the Node test runner.
04 / Engineering constraints

What it does—and does not.

Constraints visible in source, workflow definitions and repository contents as inspected for this build.

GitHub is the storage layer

Daily and weekly files, README and JSON are committed through the GitHub Contents API. There is no database or local persistent store.

UTC defines the calendar

Daily paths, issue fallback dates, activity windows, streaks and weekly periods are calculated in UTC.

Activity is a 24-hour snapshot

Commits, merged PRs and releases are read from up to 100 returned items per endpoint. It is not a complete analytics/event stream.

Public release state is empty

No GitHub release or binary asset is published at the time this manual was built. A version download cannot be offered yet.

Validation is deliberately small

The current test suite contains five Node built-in tests for Markdown section replacement. It does not run integration tests against GitHub APIs.

GitHub Actions is the execution host

Workflows use Ubuntu runners and Node.js 22. No Windows, Android, macOS, or self-hosted runtime is defined.

Issue form is a GitHub interface

Capture uses the GitHub Issue Forms schema. The workflow runs when a matching issue is closed—not on draft or every edit.

Dashboard writes are sequential API calls

README and latest.json are separate Contents API writes. The repository does not implement a transaction spanning both files.
